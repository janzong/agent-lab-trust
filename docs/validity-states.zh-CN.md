# 有效态与「缺失≠零」规则

## 范围

本说明定义 `agent-lab-trust` 使用的三个有效态，以及催生这条规则的测量问题。写给需要决定“一个数到底能不能报出来”的工具作者与规范作者。

## 三个状态

每个被测结果有且只有三种状态：

1. **valid（有效）**——测量已执行，且前置条件成立。
2. **invalid（无效）**——测量已执行，且某个声明的检查失败。
3. **unknown-or-unattributable（未知或不可归因）**——测量所需的事件缺失、被阻断，或无法归因到该主体。

第三个状态是强制的。把它折叠进另外两个，会产生静默错误：缺失事件被渲染成自信的 `0`，或不可归因的效果被渲染成已确认的结果。

## 缺失≠零规则

> **缺失事件必须报 unknown，绝不报 0。**

计数器只有在该主体确实被评估、且观察到零个匹配事件时，才允许报 `0`。如果记录路径根本没被走到——字段从未写入、调用点从未传标识符、或归因无法解析——正确值是 unknown，不是零。

这条规则讲的是测量语义，不是算术。unknown 与已知值求和必须得到 unknown；看板与下游消费者必须向下传播 unknown，或拒绝展示数字。

## 讨论中使用的脱敏事故

一个研究报告系统把一个类布尔字段复用为两种含义：工作流状态（“该条目已转为任务”）与消费计量（“该条目被某产出引用”）。报告累计产生数千次引用，但消费侧记录为零，因为引用路径从不写该字段。看板与优先级排序把这个自信的 0 读成“从未被使用”。

修复把两件事分开：

- 建立独立的引用事件账，带每个产出的标识符；
- 所有消费调用点都传这些标识符，包括其他产出为空的路径；
- 先红后绿的回归测试，含坏输入容错；
- 部署前独立复算。

## 计费映射

同一三态在计费语义中独立出现：

| 测量 | 计费 |
|---|---|
| valid | billable（可计费） |
| invalid | non-billable（不可计费） |
| unknown-or-unattributable | unattributable（不可归因） |

共同失效模式完全一致：一个字段同时承载工作流决策与测量值时，第三态被静默删除。

## 测量窗口有效性

一次测量可以成功执行，却仍不构成有效证据：它可能在对象到达终态之前运行。我们称之为**窗口无效（window-invalid）**测量。

脱敏示例来自自动化报告评分。某质量评分器只检查每份报告的前六千字符，而参考文献与定稿器输出在文档更靠后追加。评分代码执行了、返回了分数、看起来完全 valid——但它测的是一个前缀，不是完整产物。下游消费者看到的，是对评分器从未读过的内容给出的自信分数。

规则：

> 只有在终态对象上完成的测量才可标记 valid。如果对象仍在写入、被隐式上限截断、或在测量输入采集之后才组装完成，状态应为“窗口未闭合的 unknown”，而不是 valid。

实操守则：

1. 给评分器传显式内容哈希或终态产物 id，不传可变的活动缓冲区。
2. 存在截断上限时记录被测字节范围，并外显覆盖率。
3. 测量后的写入一律视为自动失效事件。
4. “对象未定稿”宁可失败闭合，也不要静默给前缀打分。

## 实现守则

1. 永远不要从工作流状态字段推导使用计数。
2. 用稳定主体标识符记录显式事件。
3. 区分“观察到零事件”与“事件流不存在”。
4. 聚合时向下传播 unknown；不要强转为零。
5. 修账本之前，先为缺失场景写失败的测试。
6. 只给终态产物评分；对象仍在写入时，绝不给前缀打分。
